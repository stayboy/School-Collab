# Topic Edit → CodedValue + Tenancy Override + Template Code Format

## Status
Proposed (cg/8 follow-up). Split into shippable PRs below.

## Problem
The current `TopicEditDialog` (grade-detail Subjects card kebab → "Edit name")
renames a `Topic` directly via `UpdateTopicAsync` → `PUT /students/topics/{id}`
with `Name + DisplayOrder`. It does **not**:
- go through the **CodedValue + tenancy override** mechanism (so edits mutate the
  global coded-value blueprint directly — the wrong tenancy model);
- allow editing the **code**;
- derive a topic's code from a **template rule** (the repo's segment-based
  `EntityCodeRule` code generator).

## Requirements (user-confirmed)
1. **Code override is supported.** Topic edits can change name **and** code via the
   tenancy-override mechanism.
2. **Cannot override Code AND Description at the same time.** If a caller tries to
   set both, a **new CodedValue must be created** instead of overriding.
3. **A CodedValue created that way is tenancy-scoped** and **reserved for the tenant
   that created it**, until it is **system-wide approved** for global usage.
4. **Newly added topics must use a code generated by a template rule.** e.g.
   "computer science" → **`CS01`** ("worded split start letters" → acronym prefix
   `CS` + numeric sequence `01`). This requires a new segment type in the
   `EntityCodeRule` template model (name-derived initials), and the topic-create
   flow must generate codes via `IEntityCodeGenerator` instead of accepting a
   free-form code.
5. **Topic dialog edits only write the tenant override, not the main CodedValue —
   except when no tenant override exists** (then the main CodedValue is edited).

## Current-state summary (what exists)
- **Topic ↔ CodedValue**: `Topic` has `CodedValueId` ("operational peer", §3.2).
  `CreateTopicForGrade` / `GetOrCreateTopic` accept a `CodedValueId + Code + Name`.
- **CodedValue tenancy** (`CodedValue.TenantId`): `null` = shared blueprint
  (CSV-seeded, overlaid per tenant via `TenantCodedValueOverride`); real tenant id
  = tenant-owned row. `Guid.Empty` is invalid.
- **Tenant override** (`TenantCodedValueOverride`): `TenantId`, `GlobalCodedValueId`,
  `OverriddenName`, `OverriddenDescription`. `UpsertCodedValueOverrideHandler`
  (PUT `/api/coded-values/{id}/override`) currently overrides **Name + Description
  only** — there is **no code field**.
- **Code generation** (`IEntityCodeGenerator.GenerateAsync(ruleCode)` →
  `EntityCodeGenerator`): loads the active `EntityCodeRule` by `Code`, applies tenant
  overrides, advances per-segment sequence state atomically. Segment types today:
  `Fixed`, `NumericSequence`, `AlphabeticSequence`, `AlphanumericSequence`. There is
  **no acronym / word-initials-from-name segment**.
- **CodedValueCreate** (`CodedValue.Create`) is tenant-agnostic; the create command
  sets tenancy via the repository. **No "reserved/pending global approval" state** exists.

## Design

### A. Extend the CodedValue override to support Code
- Add `OverriddenCode` to `TenantCodedValueOverride` (nullable).
- Extend `UpsertCodedValueOverride` command + `CodedValuesApiClient.UpsertOverrideAsync`
  to accept an optional `code`.
- **Rule (requirement 2):** if `code` **and** `description` are both supplied for an
  override, reject the override and instead **create a new tenant-scoped CodedValue**
  (see C).
- The resolved `CodedValueDto` must reflect the overridden code (add `DefaultCode` /
  expose `Code` = effective). Mirror how `DefaultName` already works.

### B. New "worded initials" segment type for the template
- Add `SegmentType.WordInitials` (name-derived acronym prefix, e.g. `CS`) that renders
  the first letter of each significant word in the **entity's name**, then a numeric
  sequence — producing `CS01`.
- The generator needs the entity **name** at generation time. Extend
  `IEntityCodeGenerator` with an overload that accepts a name-derived initials source,
  or add a `nameHint` parameter to `GenerateAsync` used only by `WordInitials` segments.
- Seed a topic code rule (e.g. `TOPIC_CODE`) with a `WordInitials` + `NumericSequence`
  template.

### C. Tenant-scoped CodedValue + reserved/pending-approval
- When override is impossible (code+description both set), create a **new CodedValue**:
  - `TenantId` = current tenant (tenant-owned, isolated).
  - Add a **provisional / reserved** state flag (e.g. `IsProvisional` or a
    `ReservedByTenantId`) so it is hidden from other tenants until a **system-wide
    approval** promotes it to the shared blueprint (`TenantId = null`) and, if
    desired, registers a blueprint for reuse.
- Add an admin approval surface (Settings coded-value admin) to review pending
  tenant-created CodedValues and approve/demote to global.

### D. Topic dialog edits only touch the tenant override
- Rework `TopicEditDialog` to:
  - load the **CodedValue** backing the topic (`Topic.CodedValueId`);
  - present Name + Code (+ optional Description);
  - if a tenant override exists → write the override (`UpsertOverrideAsync`);
  - if no override exists → write the main CodedValue (edit in place) — requirement 5;
  - if both code+description changed → fall back to **new tenant-scoped CodedValue**
    (C), then point the Topic at it.
- Keep the topic-name display reading the **resolved** (override-aware) name/code.

### E. New topics use template-generated codes
- In the topic-create flow (`CreateTopicForGrade` / `GetOrCreateTopic` / the grade
  detail add-topic UI), replace free-form code entry with **`IEntityCodeGenerator`**
  using the seeded `TOPIC_CODE` rule, so "computer science" → `CS01`.

## PR breakdown (each shippable, green, stacked)
Proposed order (base = current `cg/8-grade-detail-polish` tip, or wherever the cg/8
commit lands):
1. **tcv/1 — override code field (backend + client + DTO).** Add `OverriddenCode` +
   `DefaultCode`; extend upsert command/client to accept `code`; extend
   `CodedValueApiClient.UpsertOverrideAsync`; unit tests.
2. **tcv/2 — WordInitials segment + code generation.** New `SegmentType.WordInitials`,
   generator overload with name hint, seeded `TOPIC_CODE` rule; tests for
   `"computer science" → CS01`.
3. **tcv/3 — tenant-scoped provisional CodedValue + approval.** New reserved state on
   `CodedValue`, create-when-override-impossible path, admin approval surface;
   tests for tenancy isolation + approval.
4. **tcv/4 — topic dialog rework (override-first).** `TopicEditDialog` edits the
   tenant override (or main CodedValue when no override), code editing, fallback to
   new tenant-scoped CodedValue; bUnit tests.
5. **tcv/5 — template-generated topic codes in the add flow.** Wire `IEntityCodeGenerator`
   into topic creation; UI shows generated code; tests.

  integration event / outbox flow? What happens to tenant-created CodedValues if
  rejected — hard delete or remain tenant-scoped?
- **Existing free-form topic codes**: migrate them onto the rule or leave legacy codes
  untouched (codes stay unique)?
