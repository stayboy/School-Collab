## 3. Deviations from the plan

1. **`EmailProviderKind` enum + pure `EmailSenderSelection` added** — the plan asked for "a pure, unit-testable choice". A pure function returning an enum, plus a DI test asserting the resolved `IEmailSender` type for both configurations, makes both branches genuinely testable (no reflection needed).
2. **`IContactAddressResolver` implementation uses the existing `GET /contacts?ownerType=..&ownerId=..` endpoint** and matches the contact id client-side, because the Students API exposes no `GET /contacts/{id}` returning `ContactDto` (only `/{id}/subscription`). No new Students endpoint was invented.
3. **Unresolvable address ⇒ `Skipped` (reason `"no delivery address resolved"`)** — the plan only mandated `Skipped` for a missing/expired token. A row with an empty `To` could never be delivered, and a `Failed` row would pollute the ar-17 failure list with a non-transient condition; `Skipped` is the consistent terminal outcome.
4. **MailKit pinned to 4.18.0 rather than an older line** — 4.14.0 raised NU1902 vulnerability warnings (MailKit + MimeKit) that would have shipped as new warnings.
5. **`NotificationDispatchService` is registered in `AddAssignmentNotificationDelivery` (Core) while the hosted service + address resolver are registered by `AddNotificationDispatchSweep()` (Api)** rather than one shared extension.
6. **`smtp-user` / `smtp-password` are not committed to `appsettings.json`** — a secret parameter must not carry a committed default (matching the existing `openrouter-api-key` precedent); documented in §2/§10 of `configuration.md`.

The AppHost MailPit container was added but not launched in this pass.
- **`StudentsContactAddressResolver` has no test** — it needs a `ScriptedHandler` HTTP test; not written (plan's binding list did not include it). The broadcaster tests use a stub resolver.
- **Not run**: full 10-project `dotnet test` matrix (parent's freeze step), and `SchoolCollab.Families.Tests.Unit` / Students suites (untouched by this change, but not re-verified here).
- **No integration test asserts the endpoint route itself** (`GET /assignments/{id}/notification-failures`); the handler is unit-tested, the route is only compile-verified.
- `Smtp:UseStartTls` is not an AppHost parameter (code default `false`, overridable via configuration); documented in §11 only.

## 5. Decisions made where the plan left latitude

- **Address resolution is skipped for recipients with no unexpired token** — avoids an HTTP call per skipped recipient; skipped rows carry an empty `ToAddress`/`Subject` (except the no-address case, which carries the rendered subject).
- **`Attempt` increments on success too** (the row records attempts made, not failures only); the cap therefore reads as "5 attempts made". `NotificationRetrySchedule.Next(attempt)` is indexed by attempts made, so `Next(5)` = terminal.
- **SMS/WhatsApp rows persist the same rendered text in `BodyHtml`** (one payload column; the channel column selects the sender).
- **`Skipped` rows get `BodyHtml = string.Empty`** and a reason; `Sent`/`Failed` rows always carry the full rendered payload.
- **The broadcaster calls `SaveChangesAsync` on the scoped `AssignmentsDbContext`** after adding its rows (the publish handler's later `SaveChanges` is then a harmless no-op). Alternative (deferring the save to the caller) was rejected because it would make the v1.1 contract unobservable in isolation.
- **Drain cadence = 1 minute** (`NotificationDispatchSweepService.Interval`); retry timing itself comes from the stored `NextRetryAt`.
- **Cross-tenant drain read** uses `IgnoreQueryFilters(["Tenant"])` for the candidate list only, with the per-row dispatch inside `RunWithExplicitTenantAsync` — the exact `ArchiveSweeper` + `AssignmentRepository.ListDueForArchiveAsync` precedent (no `SuppressTenantGuard` usage anywhere in the Assignments context).
