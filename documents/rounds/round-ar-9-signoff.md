## Plan

### Goal

Execute the **C1 sign-off domain + C2 sign-off UI + C4 locking** slice (impl-details §2 WS-C bullets 2–7 minus certificates; breakdown §4 Phase 3 items 2–3 minus C3). Concretely:

1. **Per-(assignment, ward) sign-off state** — extend `AssignmentSubmission` with `SignOffState (None|AwaitingSignature|Signed)` + `SignedAt` + `FinalizedAt` + `ExpectedSignerGuardianId`; `AwaitingSignature` set automatically on the first recorded submission when the assignment `RequiresSignature`; `Signed`/`Finalized` **block further submissions** (the `RecordSubmission` guard — C4 locking).
2. **`SignatureEvent`** — immutable standalone tenant audit entity (`signature_events`): who signed, when, IP, user-agent, consent text shown, signature type (Typed|Click) + typed name; one row per (assignment, student) — DB-unique backstop + state-machine idempotency (second sign → 409, never a second event row — NFR line 115).
3. **`TenantSignatureConsentText`** (Settings.Core; one row per tenant; null = embedded default) + CQRS + `GET/PUT /api/settings/signature-consent-text` + Admin page; resolved into the sign flow via a fail-open resolver (the ar-8 `ISignatureDefaultResolver` pattern).
4. **Sign / Reassign / Finalize commands + routes** — guardian e-sign (typed or click), teacher reassignment of the expected signer (validated against `StudentGuardian` links via students-api), teacher finalize.
5. **Status projection + surfaces** — computed per-ward sign-off rows (projection, NO stored chain enum) with student/guardian names resolved via students-api; a teacher "Guardian Sign-off" card on the Assignments Detail page; a guardian e-sign page (`/assignments/{id}/students/{studentId}/sign-off`) with review summary, consent display, typed/click signature, and the acting-guardian self-select (v1 dev posture); a reassign dialog.
