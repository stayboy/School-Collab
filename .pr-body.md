## Summary

Centralizes feature-flag configuration in `SchoolCollab.Config` so flags are no longer duplicated across API and Admin `appsettings.Development.json` files.

## Changes

- Added `ConfigFeatureFlagConfigurationProvider` and `FeatureFlagConfigurationExtensions` in `SchoolCollab.Core`.
- `AddRemoteFeatureFlags` resolves Aspire service-discovery URIs (`https+http://config`) from the environment variables Aspire injects, so the remote Config API is actually reachable when running under AppHost.
- Consumers now call `builder.Configuration.AddRemoteFeatureFlags("https+http://config")` at startup to load flags from the Config API.
- Wired `SchoolCollab.Config` into the Aspire AppHost; all APIs and Admin reference it and wait for it.
- Made `GET /api/features` anonymous so services can read flags before their own auth stack is configured.
- Added `src/SchoolCollab.Config/appsettings.Development.json` with `FEATURE:DisableOIDCAuth: true`.
- Restored `src/SchoolCollab.Admin/appsettings.Development.json` with the same flag so Admin can run standalone when the Config API is not available.
- Removed scattered `FeatureFlags` sections from API `appsettings.Development.json` files.
- Refactored `AddAuthAndTenancy` to read `FEATURE:DisableOIDCAuth` directly from `IConfiguration`, removing the temporary `BuildServiceProvider()` anti-pattern while keeping the same behavior for both remote and local flags.
- Added unit tests for `ConfigFeatureFlagConfigurationProvider`.
- Added regression tests for Aspire service-discovery address resolution in `FeatureFlagConfigurationExtensions`.
- Updated `src/SchoolCollab.Config/README.md`, `.github/copilot-instructions.md`, `.github/merge-policy.md`, and `documents/solution/centralized-feature-flags-implementation.md`.

## Verification

- `dotnet build --configuration Release`: 0 errors (NU1900 warnings are network-related vulnerability-feed errors only; pre-existing nullable warnings unchanged).
- `dotnet test --filter "FullyQualifiedName~Tests.Unit" --ignore-exit-code 8`: 281 passed, 0 failed.

## Related

Closes the config-drift issue where `codedvalues.api` was not loading because `FEATURE:DisableOIDCAuth` was only set in Admin's local config and the API still required OIDC.
